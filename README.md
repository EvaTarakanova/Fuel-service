О приложении:
Прототип мобильного сценария заправки для водителя грузовика. Водитель выбирает АЗС рядом, топливо, колонку и объём, запускает заправку и следит за её состоянием.

Главный экран показывает рейс и доступный лимит. 
Дальше пять шагов: выбор АЗС (в радиусе 60 км, сортировка «Ближе / Дешевле», отметка «Дешевле всего»), 
параметры (топливо, колонка, литры), 
процесс заправки (отсчёт на пистолет, прогресс налива, отмена), 
итог (залито, списано, остаток лимита) и кнопка «Заправить рефрижератор». Сначала выбирается топливо, 
потому что колонок с нужным топливом может быть мало. Максимум литров считается как меньшее из ограничения АЗС и «доступно ÷ цена», 
а подпись объясняет, что ограничило.

Задание 1: Расхождения и проблемы, найденные в документах
1.	Водители не понимают, что такое лимит
Решение: Надпись «лимит на топливо» заменена на «Доступно сейчас»
2.	Холд имеет разные значение у диспетчера и в API.
Решение: Диспетчер говорит, что после неудачи холд висит до суток, а в API резерв снимается сразу при завершении или отмене. Приложение показывает резерв только на время заправки, а старые холд не видит, потому что API не отдаёт историю
3.	Водители не знают, сколько залить исходя из лимита
Решение: По выбранной АЗС отображается максимум, сколько можно залить
4.	У Колеса вместо цифр на колонках буквы
Решение: В приложении для Колеса цифры меняются на буквы, но также отображаются и цифры
5.	Дизель есть не на всех колонках
Решение: В приложении сначала происходит выбор типа топлива, а только потом выбор колонки. Свободные колонки отображаются исходя из типа топлива
6.	Водители не знают, как быстро нужно вставлять пистолет
Решение: Отсчет 40 секунд в приложении. API отменяет заказ через 60 секунд
7.	Слишком маленькие кнопки
Решение: Размер всех кнопок установлен на 85 пикселей
8.	Вопросы по поводу заправки рефрежиратора
Решение: Добавлена кнопка на вторую заправку
9.	Водители не знают, где чек
Решение: В приложении отображена подсказка, что чек придет утром диспетчеру
10.	Лимит водителя из разговора в API указан 15000, хотя и в макете, и в разговоре упоминается 20000
Решение: Оставлен лимит из API
11.	Нельзя отменить заправку при начале залива топлива, хотя диспетчер отмечает, что такая возможность есть, если залилось меньше половины
Решение: Заправку можно отменить, пока топливо не начало заливаться
12.	Обрыв связи и двойной заказ. API в 10% случаев теряет ответ, хотя заказ создан. 
Решение: один clientRequestId на заказ, сохранённый в localStorage до отправки; повтор с тем же id вернёт тот же заказ; после перезагрузки приложение само находит активную заправку
13.	API иногда меняет цену на 0,3–1,2 ₽ при заказе 
Решение: показать старую и новую цену, подтверждение заново.
14.	Недолив. В API ~18% заправок заканчиваются раньше заказанного. В разговоре про это нет. Решение: итог показывает «заказано / залито», разница возвращается на лимит.

Задание 3: Принятие продуктового решения

Мера: максимум литров зависит от цены АЗС. 

Для выбранного топлива приложение считает среднюю цену по округе: медиану цен на АЗС в радиусе 60 км от водителя. Если цена выбранной АЗС выше средней не больше чем на 15%, ограничения нет, и максимум остаётся обычным. Если цена выше, максимум литров вдвое меньше (долю и допуск задаёт владелец парка), но не ниже минимума АЗС в 10 л. 

Не блокируем действия водителя, на дорогой АЗС он по-прежнему может заправиться, просто не на весь лимит, а остаток достанется более дешёвой АЗС дальше по маршруту. 

На экране параметров мы объясняем причину («Цена выше средней по округе: 74,50 против 72,10 ₽, максимум здесь 65 л) и показываем самую дешёвую АЗС рядом с расстоянием до неё, чтобы водителю не пришлось звонить диспетчеру за советом. Если дешевле АЗС в радиусе нет, ограничение не применяется, чтобы водитель не застрял на единственной.

Отвергнутые альтернативы: 

1)	Подсказка о переплате. Сообщение вида «дороже самой дешёвой на 3,2 ₽/л, переплата около 420 ₽» ничего не ограничивает. Водитель нажмёт «всё равно заправиться», а вторая жалоба, весь лимит за раз, остаётся нерешённой.
  
3)	Запрет заправляться на определённых АЗС. Цены меняются каждый день, поэтому список запрещённых АЗС быстро устареет, а поддерживать его придётся владельцу. Водитель может оказаться перед единственной дорогой АЗС и встать, значит, нужен процесс исключений через диспетчера.

Метрика ошибки: среднее число заправок на рейс. Его нужно измерить до запуска. Если через месяц оно выросло больше чем на 30%, значит, ограничение заставляет водителей делать лишние остановки, и потерянное время дороже сэкономленной разницы в цене. Тогда мера ошибочна, и её нужно снять или смягчить.
